# Repository practices

- Write pull request titles and commit subjects in lowercase, using a concise type prefix such as `feat:`, `fix:`, `refactor:`, `revamp:`, or `chore:`. Choose the type that describes the change and use clear, human-readable wording.
- Keep pull request descriptions and commit message details simple and direct. List what changed and include relevant validation when useful.
- Group changelog entries by type, such as features, fixes, bug fixes, and security fixes. Keep each entry short and easy to understand.
- When creating branches or worktrees, use descriptive names without `t3/`, `T3Code`, or similar T3-specific prefixes.
